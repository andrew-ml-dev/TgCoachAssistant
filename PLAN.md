# Telegram-бот для похудения — план

## Context

Нужен личный Telegram-бот (один пользователь), который ведёт вес и калории, держит дневной бюджет калорий и предупреждает об остатке, настойчиво напоминает взвеситься, разбирает еду по текстовому описанию и подсказывает, как худеть эффективнее. Желаемый темп: **−2 кг в неделю**. Проект с нуля: папка `app/` пустая. Бот живёт на Raspberry Pi 5 (`192.168.8.112`). Claude API используется экономно, без картинок.

Главная идея эффективности: бот **вычисляет реальный расход (TDEE) из ваших же данных** (тренд веса + съеденное) и раз в неделю корректирует бюджет. Это чистая математика без затрат на API.

### Про цель −2 кг в неделю

2 кг жира ≈ 15 400 ккал, то есть дефицит **≈ 2 200 ккал в день**. Это выполнимо только при большом расходе: при TDEE 2 800 пришлось бы есть 600 ккал в день. Поэтому движок работает так:

- Желаемый темп (2 кг/нед) хранится как цель, и бот всегда показывает, какой дефицит для неё нужен.
- Бюджет еды не опускается ниже **пола** (по умолчанию 1 500 ккал для мужчин, 1 200 для женщин; меняется в настройках с предупреждением).
- Бот честно показывает **достижимый темп** при текущем расходе («при вашем расходе 2 900 и поле 1 500 реальный темп ≈ 1.3 кг/нед») и сколько активности нужно добавить, чтобы приблизиться к 2 кг («+700 ккал активности в день ≈ 90 минут ходьбы»).
- Учтённая активность (шаги, тренировки) увеличивает расход и приближает к цели без снижения еды.
- В первые 1–2 недели весы могут показывать −2 кг и больше за счёт воды; бот отделяет это от тренда.

## Стек

- Python 3.11+, **aiogram 3** (long polling: не нужен белый IP)
- **SQLite** (aiosqlite), **matplotlib**; планировщик — встроенный цикл asyncio раз в минуту (состояние в БД), без APScheduler
- **anthropic** SDK, модель **`claude-haiku-5-5`** ($0.10 / $0.50 за 1M токенов), `effort: low`, структурированный вывод через `client.messages.parse()` + Pydantic. Модель задаётся в `.env`
- На Pi запускается как сервис **systemd**

## Контроль калорий

- **Дневной бюджет** = расход − дефицит под темп, не ниже пола. Показывается в каждом ответе на запись еды: съедено, осталось, полоса заполнения.
- **Предупреждения по порогам** (каждое один раз в день):
  - 75% — «осталось 400 ккал, впереди ужин»
  - 90% — «осталось 160 ккал»
  - 100% — «бюджет исчерпан»
  - превышение — сколько сверху и что это значит для недели («+350 ккал = −45 г к недельному результату»), без нотаций
- **Проверка до еды** `/can шаурма` (или кнопка «Можно ли?»): бот оценивает блюдо и отвечает, влезает ли оно в остаток и что останется, ничего не записывая. Кнопка `[Записать]`.
- **Недельный бюджет**: перебор в один день распределяется на оставшиеся дни недели (бот предложит: «−60 ккал в день до воскресенья» или «оставить как есть»). Недобор не превращается в разрешение переесть больше чем на 15%.
- **Планирование дня**: в середине дня подсказка, сколько осталось на оставшиеся приёмы пищи («на ужин ~480 ккал, белка нужно ещё 60 г»).
- **Белок**: отдельная цель (1.8–2.2 г на кг целевого веса) — при большом дефиците это главное для сохранения мышц. Вечером предупреждение, если белка мало.
- **Активность**: по умолчанию в бюджет еды не добавляется (так темп выше). В настройках можно включить возврат 50%.
- **Вечернее напоминание**, если за день внесено подозрительно мало (меньше 50% бюджета): «всё записано?»

## Остальные функции

- **Профиль и цель** (`/start`): пол, возраст, рост, вес, целевой вес, активность, темп, часовой пояс, время подъёма.
- **Вес**: число с точкой или близкое к последнему весу — вес; `450` / `450 ккал` — калории; при неоднозначности кнопки «⚖️ Вес / 🔥 Калории».
- **Настойчивые напоминания о взвешивании**: утром в заданное время, затем каждые 30 минут до отсечки (12:00), пока вес не внесён. Кнопки «Отложить на час», «Сегодня пропускаю».
- **Ввод еды, три способа**: число (без API); свои блюда, «Недавнее», «Как вчера», кеш (без API); свободный текст через Claude с одним уточняющим вопросом при неясной порции. Исправления запоминаются в личный словарь.
- **Недельный отчёт** (воскресенье): график веса с трендом, средние калории, соблюдение бюджета, реальный расход, достижимый темп, прогноз даты цели, короткий разбор от Claude (1 запрос в неделю) с паттернами и 2–3 советами.
- **Детектор плато** (тренд стоит 2+ недели) и **слишком быстрой потери** (тренд быстрее 1.5% веса в неделю дольше 2 недель).
- **`/idea`** — что съесть на остаток, чтобы добрать белок.
- **Серии**, **обхват талии**, `/undo`, редактирование записей, `/export` CSV, ночной бэкап БД.
- **`/cost`** — счётчик расходов API и месячный лимит.
- Этап 3: **голосовые** через локальный `faster-whisper` на Pi (бесплатно). Фото выключены; можно включить флагом позже.

## Движок: как всё работает

### 1. Путь сообщения

```
Сообщение → проверка доступа (ALLOWED_USER_ID)
          → ожидается ли ответ на вопрос бота? (FSM: онбординг, правка, уточнение порции)
          → классификатор (parser.py, без API):
               кнопка меню / команда        → нужный экран
               «82.4», «вес 82»             → вес
               «450», «450 ккал обед»       → калории числом
               «8000 шагов», «шаги 8000»    → активность
               остальной текст              → еда
          → обработчик → запись в БД → пересчёт дня → ответ + проверка порогов
```

### 2. Разбор еды текстом

```
текст → нормализация → поиск в food_cache и личном словаре
      → найдено целиком: ответ без API
      → не найдено: Claude Haiku (системный промпт: диетолог, русская кухня,
        типовые порции, граммы в готовом виде) → JSON по схеме:
        items[{name, grams, kcal, protein, fat, carbs, confidence}], question?
      → question есть: один уточняющий вопрос → повторный разбор
      → черновик приёма пищи → [✅ / ✏️ / ❌]
      → после ✅: meals + meal_items, результат в food_cache, токены в llm_usage
```
Правка («хлеба было 3 куска», «котлета 200 г») пересчитывается локально по пропорции; Claude вызывается, только если меняется само блюдо.

### 3. Расчёты (nutrition.py)

- **Стартовый расход**: BMR по Миффлину — Сан Жеору × коэффициент активности.
- **Трендовый вес**: `trend = trend_prev + 0.25 × (вес − trend_prev)`; пропущенные дни интерполируются. Все решения принимаются по тренду, а не по сырому весу.
- **Реальный расход** (после 14 дней данных, пересчёт еженедельно):
  `TDEE = средние ккал за 14 дней − наклон веса (кг/день) × 7700`.
  Наклон считается регрессией по сырым взвешиваниям (разность значений тренда запаздывает и занижает потерю в первые недели). Результат сглаживается с предыдущим значением (70% новое, 30% старое). Дни без записей еды в расчёт не входят.
- **Бюджет**: `max(пол, TDEE − темп × 7700 / 7)`. Достижимый темп: `(TDEE + активность − бюджет) × 7 / 7700`.
- **Прогноз даты цели**: по фактическому наклону тренда за 3 недели.
- **Пересчёт при падении веса**: расход снижается вместе с весом, бюджет обновляется каждую неделю и предлагается кнопкой «Принять».

### 4. Планировщик (reminders.py)

| Когда | Задача |
|---|---|
| Утро (время подъёма) | напоминание о весе, повтор каждые 30 мин до отсечки |
| 14:00 | план на остаток дня (если еда внесена) |
| 21:00 | вечерний итог; «всё записано?» при малом объёме |
| Воскресенье 10:00 | недельный отчёт, пересчёт расхода и бюджета |
| 03:00 | бэкап БД, очистка старых черновиков |

Задачи создаются при старте из профиля, а состояние дня (отложено, пропущено, какие пороги уже показаны) лежит в БД, поэтому перезагрузка Pi ничего не сбивает.

### 5. Данные (SQLite)

`profile` (параметры, цель, темп, пол бюджета, текущий TDEE и бюджет) · `weights` (дата, вес, тренд) · `meals` / `meal_items` · `food_cache` (нормализованный текст → разбор) · `templates` (мои блюда) · `activity` · `day_state` (напоминания, показанные пороги) · `budget_history` · `measurements` · `llm_usage`

### 6. Расход API

Один разбор ≈ 600 входных + 300–500 выходных токенов ≈ $0.0003. При 10 разборах в день, `/can`, `/idea` и недельных отчётах — порядка **$0.10–0.30 в месяц**. Кеширование промптов не нужно (системный промпт короче минимального кешируемого размера); экономия идёт от локального кеша и шаблонов. При достижении месячного лимита текстовый разбор отключается, ручной ввод работает.

## Этапы

1. **MVP**: профиль, меню, вес + тренд, еда (число и текст), подтверждение и правки, экран «Сегодня» с остатком и порогами, напоминания о весе, деплой на Pi.
2. **Умная часть**: мои блюда и кеш, `/can`, активность, недельный бюджет, адаптивный расход, недельный отчёт с графиком и разбором, плато, вечерний итог, `/cost`.

## Слабые места плана

- **Точность оценки еды по тексту**: ошибка 20–30% на отдельном блюде неизбежна. Систематическую часть компенсирует адаптивный расход; точнее всего работают граммы с кухонных весов и сохранённые «мои блюда».
- **Всё держится на ежедневных записях**: при пропусках адаптивный расход считается хуже. Поэтому напоминания и ввод в одно нажатие важнее любых «умных» функций.
- **Темп 2 кг/нед** для большинства недостижим за счёт одной еды; бот покажет достижимый темп, а не будет подгонять бюджет под цель.
- **Объём**: функций много, поэтому сборка идёт этапами, и пользоваться ботом можно уже после этапа 1.

## Добавлено после первой версии: меню на день и протеин

- Каждое утро во время подъёма бот присылает меню на день под текущий бюджет калорий и цель по белку (1 запрос к Claude в день, около $0.002). `/menu` — показать ещё раз, «🔄 Другое меню» — пересоставить на остаток дня.
- Под меню кнопки «✅ Съел: Завтрак» и т. д.: приём пищи записывается без запроса к Claude.
- Протеин: в настройках (⚙️ Ещё → 🥗 Диета и протеин) задаётся число порций в день (0–2) и граммы белка в порции; меню включает коктейль отдельной позицией. Кнопка «🥤 Выпил протеин» в разделе «Еда» записывает порцию в одно нажатие.
- Предпочтения в еде задаются свободным текстом и учитываются в меню; вчерашние блюда не повторяются.
- Замена блюд: под меню у каждого приёма пищи кнопка «🔁 Заменить». Бот задаёт один вопрос «что не так» (кнопки «👎 Не ем: …» по продуктам или «просто другое»), заменяет только этот приём пищи на те же калории и белок, а отмеченный продукт запоминает и больше не предлагает. Отдельной анкеты вкусов нет намеренно: бот также учитывает продукты, которые пользователь сам часто записывает.

## Изменения после ревью удобства (14.11.2026)

Этот раздел важнее описаний выше, где они расходятся.

- **Главное меню**: Еда · Вес · Сегодня · Меню · Прогресс · Ещё. Кнопка «Активность» убрана: шаги не влияют на бюджет (ввод «8000 шагов» текстом остался).
- **Карточка еды**: «Исправить», «Удалить», «В мои блюда», «На вчера». Кнопки «Верно» нет: разбор запоминается сам, правка его перезаписывает, удаление убирает из памяти.
- **Мои продукты**: «продукт: название и цифры с этикетки» (или ⚙️ Ещё → 📦 Мои продукты). Дальше «название 110 г» считается локально, а в описаниях еды цифры Claude заменяются цифрами с этикетки.
- **Запись за вчера**: префикс «вчера: …» или кнопка «📅 На вчера» под записью.
- **Повтор**: одна кнопка «🕘 Повторить» вместо «Недавнее» и «Как вчера».
- **Уведомления**: предупреждений 75/90% и подсказки в 14:00 больше нет; отдельное сообщение приходит один раз в день при первом переборе. Напоминание о весе в чате всегда одно (старое удаляется). Меню приходит после взвешивания, а без него — после отсечки.
- **Прогресс**: один экран — график с подписью (темп, прогноз, расход).
- **Баланс недели** на экране «Сегодня»: сумма отклонений от бюджета с понедельника по вчера.
- **Названия приёмов пищи** — по содержимому, а не по времени суток.
- **Меню**: белка не больше цели +15%.
- **Логи**: `data/bot.log` на Pi (до 3 МБ).
- Не делаем: голосовые (есть диктовка на клавиатуре), перераспределение перебора по дням, серии, обхват талии.
- **Баланс и накопленный дефицит** (экран «Сегодня» и вечерний итог): «расход − съедено» на текущий момент и сумма дефицита за все дни с записями по вчера, переведённая в килограммы, с расчётным весом рядом с весом по тренду. Строка «баланс недели к бюджету» с экрана убрана (осталась в сообщении о переборе), шаги к расходу не прибавляются.

## Изменения после второй оценки (14.11.2026)

- **Честный темп**: если бюджет упирается в пол, экран цели прямо говорит, что выбор темпа ни на что не влияет, и показывает реальный темп и сколько активности нужно для желаемого.
- **«✅ Всё записал / ❌ Не всё»** в вечернем итоге (и на «Сегодня» после 18:00). В расчёт реального расхода, накопленного дефицита и средних за неделю идут только надёжные дни: отмеченные «всё записал» и неотмеченные с записями от 60% бюджета; «не всё» исключаются.
- **Убрано**: «Что съесть?» (/idea), «Мои блюда», кнопка разбора от тренера. Воскресный разбор от Claude остался.
- **Настройки**: Цель (целевой вес, темп, пол бюджета) · Напоминания · Диета и протеин · Сервис (расход API, CSV, профиль заново, помощь).
- **Выбор протеина** в «Диета и протеин»: какая этикетка из «Мои продукты» используется в меню.
- **Накопленный дефицит** перенесён с «Сегодня» в «Прогресс».
- **«📋 Для анализа: 7 / 30 дней»** в «Прогресс»: файл Markdown с готовым заданием, профилем, таблицей по дням и всеми записями еды — для разбора в сильной модели. Делается локально, без запроса к API.
- **«📊 Отчёт» вместо «📊 Сегодня»**: по нажатию сразу открывается сегодняшний день (самый частый случай — одно нажатие), под ним переключатель «Сегодня · 3 дня · Неделя · Всё». Переключение редактирует то же сообщение. В отчёте за период: дни по строкам (до недели), средние за полные дни, попадание в бюджет, дефицит в ккал и кг, вес по тренду. Кнопка «Итоги недели» из «Прогресса» убрана (дублировала «Неделю»); пересчёт бюджета остаётся в воскресном отчёте и /week.
- **Графики в отчёте**: «Неделя» и «Всё» приходят карточкой (тёмная тема, шрифт Inter в `bot/assets/fonts`): плитки «вес по тренду · дефицит · белок», график веса (точки, тренд с градиентом, пунктир расчётного веса по дефициту, линия цели) и под ним калории по дням (в бюджете / перебор / неполный / сегодня, линии бюджета и расхода). Две панели с общими датами вместо графика с двумя шкалами. Жиры и углеводы на график не выносятся — только средние в подписи. Кнопка «📈 Прогресс» убрана из главного меню: её содержимое (старт → сейчас → цель, темп, прогноз, реальный расход) — в подписи к «Всё».
- **Постоянная панель и закреплённая сводка**. Внизу всегда видна клавиатура, кнопки по частоте: «📦 Мои продукты · 🕘 Повторить» (запись в два нажатия) / «📊 Отчёт · 🥗 Меню» / «❓ Можно ли? · ⚙️ Ещё». Кнопок «Еда» и «Вес» нет: вес и еда пишутся в чат, подсказка — в поле ввода. Вверху чата закреплено одно сообщение-сводка (остаток, полоса, белок, вес и тренд), оно правится после каждой записи и раз в минуту, а не создаётся заново. Меню «/» отсортировано по частоте. После обновления панели бот один раз присылает новую клавиатуру сам.
- **«⚡ Быстрая запись»** заменила «📦 Мои продукты» и «🕘 Повторить»: один экран, сверху продукты с этикеткой (📦, выбрать → ввести вес), ниже 6 последних записей (🕘, повтор в одно нажатие), внизу «➕ Новый продукт» и «🗑 Удалить продукт». Кнопка стоит первой и на всю ширину панели.

## Изменение: тренировки с часов (Polar H10, Huawei)

- Ввод одним сообщением: `трен 650`, `зал + дорожка 650`, `бег 30 мин 400`, `700 тренировка`, `вчера: трен 650`. Слово без цифры («зал») — бот спрашивает калории. Кнопка «🏋️ Тренировка» есть в «⚡ Быстрая запись».
- В расход идёт 85% цифры с часов (`WORKOUT_NET`): часы считают и базовый обмен за время тренировки, а он уже в расходе; пульсовые оценки к тому же завышают.
- Расход дня = расход в расчётах (без тренировок) + тренировка. Так считаются баланс «Сегодня», дефицит в отчётах за 3 дня / неделю / всё, расчётный вес на графике, экспорт (столбец «Тренировка»).
- Бюджет еды тренировки не увеличивают: при бюджете на полу они единственный способ ускорить темп. «Цель и темп» показывает темп с учётом средних тренировок.
- Адаптивный расход вычитает учтённые тренировки: `расход = средне съедено − средние тренировки − наклон × 7700`. Поэтому систематическое завышение часов со временем гасится.
- Коэффициент активности в анкете — только обычный день без тренировок (иначе двойной счёт).
- На графике калорий расход — ступенька: в дни тренировок выше, с подписью «+595».
- Шаги остаются справочными и в расход не входят.

## Изменение: импорт тренировок из Polar Flow

- H10 → приложение Polar Flow → облако Polar → бот (Polar AccessLink API v3). Планировщик опрашивает `GET /v3/exercises` раз в 15 минут; белый IP не нужен.
- Подключение: ⚙️ Ещё → ⌚ Polar (или /polar) → ссылка OAuth → Polar перенаправляет на `http://localhost:5000/oauth2_callback` (страница не открывается) → пользователь присылает адрес боту → код меняется на токен, пользователь регистрируется у клиента. Ключи клиента — `POLAR_CLIENT_ID` / `POLAR_CLIENT_SECRET` в `.env`.
- Импорт: калории ×0.85 в расход, название вида спорта, длительность, средний и максимальный пульс. Тренировки до начала наблюдения не берутся. Если за день уже есть ручная запись — бот спрашивает «та же?» и по кнопке убирает ручную.
- Удалённая импортированная тренировка помечается `kind='deleted'`, чтобы следующий опрос не вернул её.
- Polar отдаёт только тренировки, загруженные после подключения, и за последние 30 дней.
- Отозванный доступ: токен сбрасывается, бот один раз просит подключиться заново.
